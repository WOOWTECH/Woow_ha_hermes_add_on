## 3 測試方法與限制

- **側邊欄（HA ingress 經 Cloudflare）**：用真正的瀏覽器（headless Chromium）操作，這是使用者實際使用的路徑。另外在真正的 HA 前端頁面中，對側邊欄 iframe 測了登入、切換頁面、F5 和聊天。
- **直連 `:9119` 與區網 ingress**：測試環境不在該主機的區網內，SSH 也不允許轉發 port，所以這兩條路是從 HA 主機上用 HTTP/API 比對：資料、檔案位元組、session 紀錄和狀態碼。
- 因此，只和瀏覽器行為有關的項目只能在側邊欄測，例如斷網後恢復、輸入框行為。這些在側邊欄全部通過。之前 0.1.5 的測試已經在三條路上都用瀏覽器比對過。

## 5 上游 Hermes 問題

以下問題三條路徑都一樣，與 add-on 無關。

新發現：
1. **聊天重新連線後輸入框多出字元**：重新整理或重新連線後，輸入框會多一個 `l`，下一則訊息會把它一起送出。原因是重新連線時 PTY 重播了 TUI 的啟動查詢，或送了強制重繪的 Ctrl+L，被 TUI 當成輸入。
2. **從 MCP 頁新增伺服器後，已開著的對話看不到新工具**：要執行 `/reload-mcp` 或開新對話才看得到。
3. **在已開著的聊天裡，重新啟用的 skill 無法使用**：輸入 `/skill` 時畫面顯示「Loading skill」，但實際沒有送出任何內容。
4. **從 skill hub 安裝後，Skills 列表不會自動更新**：dashboard 也沒有解除安裝按鈕，也沒有刪除自訂 skill 的功能。
5. **在設定頁存檔時，整數值的小數點被去掉**：`30.0` 會變成 `30`。
6. **kanban 頁面每次開啟會建立兩條相同的 WebSocket**，每個事件因此收到兩次。

先前已知：快速打字會掉字、聊天側欄的 session 列表不會即時更新、kanban 刪除卡片不會即時同步且附件沒有被刪除、Webhooks 頁顯示 `localhost:8644`。

## 6 平台限制

- 經 HA ingress 下載時，Content-Type 少了 charset。這是 HA Supervisor 的 `ingress.py` 造成的，檔案內容完全相同。
- 經 Cloudflare 時，頁面會多出 Cloudflare 自己的 `/cdn-cgi/challenge-platform` 請求。
- MCP OAuth 的回呼網址預設是區網 IP，這是設計如此。要從外網完成 OAuth 登入，需要設定 **Dashboard public URL**，DOCS 有說明。

## 7 清理

- **自動清理**：測試建立的 sessions、排程、MCP 伺服器、skills、kanban 卡片、webhook 訂閱、profile、環境變數、記憶和檔案都已刪除。
- **手動補清**：有兩個驗證 agent 做到一半被中斷，另外補清了以下項目：
  - MCP 伺服器刪除後，上游沒有停掉仍在執行的 `server-everything` 行程，已手動結束。
  - 1 個 webhook 測試 session。
  - 1 個 API 冒煙測試 session。
- **最後狀態**：session 數為 0，沒有任何 `T-` 開頭的項目。

## 8 建議

- add-on 本身不需要修改。
- 上游問題中，1（輸入框多出字元）、2（MCP 工具）和 3（skill 無法使用）會影響日常使用，建議回報 NousResearch。
- 要從外網使用 MCP OAuth，需要設定 Dashboard public URL，並在 Cloudflare 開放回呼路徑。
