# Hermes Paseo HA Integration Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver and verify the Hermes Paseo plugin on an isolated Home Assistant add-on, publish the tested add-on through the existing release pipeline, and maintain a verified Gitea pull mirror of the public plugin.

**Architecture:** Preserve the native Hermes plugin installer and login. Vendor the reviewed four-file s6 Dashboard adapter into the HA image; configure a second exact, administrator-owned HA Ingress Origin through an optional add-on setting while preserving the existing public Dashboard URL for OAuth/LAN. GitHub remains the source; Gitea pulls its Git refs on a schedule.

**Tech Stack:** Hermes 0.22.5, Paseo 0.11.2, Python/FastAPI, Node, s6, HA Supervisor/Ingress, GitHub Actions/GHCR, Gitea API, Playwright, Kubernetes.

---

### Task 1: Establish source and test environment
- New independent worktrees: plugin `work/hermes-paseo-ha-plugin-20261026`; add-on `work/hermes-paseo-ha-20261026`.
- Read repository release rules. Inventory a dedicated HAOS VM and identify a separate candidate add-on slug/profile/ports. Do not modify other workloads.
- Record original source/image/version and environment ownership. Use existing credential helpers without emitting secrets.

### Task 2: Exact HA Origin support in plugin and host
- Modify `hermes_paseo.py`, `dashboard/plugin_api.py`, `host/dashboard_control.py` and tests.
- Allow operator-only `HERMES_PASEO_INGRESS_ORIGIN` as a second exact Origin. Preserve primary private Origin storage and existing installation compatibility.
- Add behavior tests for LAN and Ingress accepted, foreign origins, invalid configuration, query selectors, cross-site metadata, missing auth, arbitrary forwarded headers denied. All reload/disable/remove paths must use the same policy.
- Run `python -m unittest discover -s tests -p 'test_*.py'`, `npm test`, and existing browser suite. Verify real prefix-aware SDK and automatic route navigation in HA.

### Task 3: HA image adapter and configuration
- Vendor four adapter files with commit/hash provenance under `hermes/vendor/paseo/`.
- Modify `hermes/Dockerfile` to install read-only adapter and native-compatible CLI wrapper.
- Add optional `paseo_ingress_url` in `hermes/config.yaml`, `hermes/translations/en.yaml`, `hermes/translations/zh-Hant.yaml`; map to validated Origin in `hermes/rootfs/etc/cont-init.d/00-woow-options`.
- Add adapter/image tests and extend `.github/workflows/publish-hermes-addon-images.yml` checks. Preserve existing port/options/data and user tool permissions.
- Add HA-specific installation/upgrade instructions and changelog; bump version only with a tested release candidate.

### Task 4: Actual HA candidate acceptance
- Use a separate candidate slug and data directory on the verified dedicated test host, distinct ports, unchanged existing add-ons.
- Build/boot candidate; install plugin using native installer. Test authenticated sidebar and LAN APIs, startup onboarding, Dashboard reload, official Paseo pairing, models/modes, real replies when a valid model quota is available, explicit stop/start, disable/re-enable, addon restart and persisted pairing.
- Test unauthenticated and cross-origin denial. Use nonsecret fixtures and clean up only task-created sessions/files. Record unsupported/unavailable items accurately.
- An emulator or native tool call is not a substitute for an actual HA browser or real model response.

### Task 5: Gitea mirror
- Verify organization/name permissions, create a public Git pull mirror from the public GitHub repository without source credentials.
- Verify main and release tags equal source; trigger sync and verify configured interval. Explain release binaries versus Git tags.

### Task 6: Release and synchronize
- Review changes and execute required checks. Push branches and open PRs; respect main-through-PR rules. Existing repository policy uses required checks as approval, no separate human gate.
- Release plugin first so HA provenance pins a published commit. Merge tested add-on PR only after required checks and live acceptance; verify image public, release exists, Store source-notification sync completed and source digests match.
- Verify mirror catches new plugin main and tags. Publish sanitized acceptance report with evidence and remaining constraints. Never publish credentials or pairing URLs.
